## Initial findings (resolved in the follow-up above)

### P2 — Text corner resize does not resize the text

Reproduction: add text, set `QA 08 Sep` (font size 2), drag its lower-right
corner approximately 35 px right and 33 px down. Selection width changed from
87 to 112 logical pixels, but height stayed 20 and font size stayed 2. Setting
Text size to 3 manually changed rendered height to 29.

Cause: `ai-theme-studio-screen.tsx`'s `onResize` only updates width/height;
text rendering derives height from font size. The existing full editor has
text-specific resize handling. Users can currently resize text via Text size,
but the visible corner handle promises a change it does not deliver.

### P2 — Preview weekly values disagree

The generated scene visibly renders SESSION 64% and WEEKLY 64%, while its
accessible summary reports Session 64% and Weekly 28%. The catalog sample frame
contains legacy `weekly: 64` but generic second-window values of 28. Generated
AI text/bars use the legacy weekly binding. This is a confirmed preview-data
inconsistency, not proof of incorrect live provider collection. Fix should
align the preview/template with the existing authoritative generic usage path.

### P3 — Scene suggestions remain visible when editing only an animation

Selecting the cat changes the input to “Change this animation”, but still
offers “Warmer sky” and “Add an animated cat”. Correction to the original
assessment: clicking the old suggestion already cleared selection and switched
to the whole scene; the defect was that this happened silently. There was not
evidence that a sky prompt was actually sent with an animation target. Suggestions
now match the selected target, with an explicit whole-scene switch.
